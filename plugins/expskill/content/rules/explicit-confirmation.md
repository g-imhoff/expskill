# Explicit confirmation

## Procedure

1. Present one exact proposal with scope, writes, branch plus base commit, and delivery target. Name what confirmation authorizes and what it leaves out.
2. Bind confirmation to the exact digest or proposal presented. For contracts bind the contract digest plus target identity. For setup bind the whole proposal including writes plus delivery. For plans bind each coherent part, with the last part as final confirmation into ready.
3. Stop before side effects and wait for an explicit unforced answer. Treat an explicit unforced answer as the only confirmation.
4. Revise plus reconfirm on any material change to facts, matrix, files, dependencies, commands, branch, or delivery target. Preserve unrelated confirmations. Invalidate only affected evidence, decisions, work, proof, and projections.
5. Record the confirmation digest, target identity, and decision versions covered. Derive ready only from current confirmations with no stale, unresolved, conflicting, or awaiting user state.

## Boundary

Confirm each effect on its own proposal; one confirmation covers exactly what was presented. Stop on a denied confirmation and await a new proposal. Leave merging to the user; the skill merges only with user authority for that exact revision.

## Evidence

Report the proposal digest presented, the user answer received, the bound target identity, invalidations on change, and the ready derivation with current confirmations.
