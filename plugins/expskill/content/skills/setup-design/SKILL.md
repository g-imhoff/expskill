# Setup Design
Run independently of `$design`, `$test`, and `$use-expskill`. Keep setup gates out of every other workflow.
## Activation and record state
Act only when user explicitly asks to establish, inspect, update, repair, or reconfigure this repo sketch setup or invokes $setup-design. Feature sketches go to `$design`, and production UI edits and routine tests go elsewhere. Resolve target repo and instructions, then only record branch, baseline, worktree status, and path safety as they stand. Before broad discovery inspect only canonical `.expskill/setup-design.md` and Git tracking. Classify per references/record-format.md:
- **Absent:** path empty with no tracked record. Proceed to research.
- **Ready:** regular tracked record passes format and proof checks. On ordinary invocation report path, method, copyable human and agent commands, approval rule, limitations, and reopening rule. Then stop. The report is the only action.
- **Invalid:** unsafe path or untracked occupant or tracked record fails validation. Report defects and stop unchanged unless the user explicitly requested repair or reconfigure.
Only an explicit update, repair, or reconfigure request reopens a ready record, even after drift or tool version change. Reopen ready records per `../../rules/explicit-confirmation.md`. Scope research and changes to that request.
## Research and decision
For absent or reopened records, discovery runs only with working collaboration tools. Otherwise stop before discovery and report the gap. Launch three independent bounded read-only subagents, each briefed only with repo root, credential-free facts, one question, and reading and reporting as its only actions. Fan out narrow discovery per `../../rules/bounded-fanout.md`:
1. In-repo project-native sketch or preview support, scripts, pinned versions, real UI entrypoints, and context.
2. Viable tooling for exact stack and versions, using official version-matched docs only for material local gaps.
3. Paper feasibility with real production component, providers, theme, fonts, assets, data, safe named scenario, three project-derived sizes, runtime observation, and blockers.
Each returns evidence paths or official sources, options, and limits. Allow at most one targeted second round of up to three read-only researchers for a named gap or conflict. Allow second rounds per `../../rules/bounded-fanout.md`. When no credible method exists, report evidence, alternatives, and next decision, and state the setup blocked. If real render needs production-owned changes stop blocked with evidence, paths, owner obligation, pending steps, and proof limits. Resume only after independent completion plus new explicit request. Coordinator alone picks smallest credible project-native method and handles user decisions. Identify remote, base branch, and authenticated MR/PR integration by read-only checks before proposing. Without delivery, disclose the blocker and propose only local branch and commit scope.
Present one exact proposal with location, seed and populate steps, all dev dependencies and versions, support and record paths, real UI target and context, one primary human command and any distinct agent command, one realistic named scenario, exact compact intermediate and wide project-derived runtime dimensions, canary, observer, proof steps, approval conditions, ownership and cleanup, isolated branch/worktree and baseline, commit scope, remote with head/base and ready-for-review target, and known proof limits. Bind confirmation to the exact proposal per `../../rules/explicit-confirmation.md`. Ask for explicit confirmation of whole proposal including writes and delivery and stop before install, support file, branch/worktree, commit, push, or MR/PR. Accept only explicit answers. Reconfirm on material change per `../../rules/explicit-confirmation.md`. Create the lane worktree per `../../rules/isolate-writes.md`.
## Apply and prove the confirmed setup
Recheck repo, instructions, baseline, dirty work, record state, remote, and approved scope. Recheck identities before use per `../../rules/pin-scope.md`. Reconfirm on material change per `../../rules/explicit-confirmation.md`. Create confirmed isolated branch or worktree preserving unrelated work. Create the lane worktree per `../../rules/isolate-writes.md`. Add only confirmed dev-only dependencies and preview, scenario, fixture, or agent support, and leave production UI as the real unedited component every sketch renders. Old `.ui-harness` guides and evidence directories stay in place and uncopied.
Run smallest representative canary in project-native renderer for same existing real production UI target with required context and stable realistic named state. Record runtime-observed viewport or window dimensions at confirmed compact, intermediate, and wide sizes as the only size proof. Verify exact human and each distinct agent command. State what isolation does and does not prove. A ready record or success claim needs a passed canary, required context, the real target, and all three runtime-observed sizes. Otherwise leave the record unwritten and report blocked. After proof write and validate tracked canonical record per references/record-format.md with copyable commands, scenario, sizes, approval rule, proof observations, ownership, limitations, and reopening conditions, then remove temp proof files. Verify owned-file scope, preserve unrelated changes, and keep preview and scenario imports out of production modules.
Before commit in actual checkout run `git var GIT_AUTHOR_IDENT` and `git var GIT_COMMITTER_IDENT` and follow identity instructions. Fix conflicting config or env overrides first. Commit only approved setup-owned paths, with any authorship trailer naming a human. Verify authors with `git show -s --format='%an <%ae> | %cn <%ce>' HEAD` before push. Preserve others authorship on replay. Previews, commands, records, and MR/PR text name credentials only by env var name. Push confirmed head and create ready-for-review non-draft MR/PR via authenticated host CLI or API. Verify real URL, head, and base. Leave merging per `../../rules/explicit-confirmation.md`. On remote, auth, push, or creation failure after a valid local commit, keep branch and commit, report exact missing delivery step, and claim only the local branch and commit.
## Report and stop
Report record path, copyable commands, measured three-size proof, approval rule, proof limits, checks, branch, commit, and verified MR/PR link. On failure preserve unrelated work and report partial effects and evidence. Resume changed work only under explicit scoped repair or revised confirmed proposal. Resume only on revised confirmation. Stop on denied confirmation per `../../rules/explicit-confirmation.md`. Also stop on missing researchers, unsafe prerequisites, weak evidence, failed proof, and delivery blocker.
