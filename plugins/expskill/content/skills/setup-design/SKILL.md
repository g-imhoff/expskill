# Setup Design
Establish a reusable isolated real production UI sketch method in tracked `.expskill/setup-design.md` with a verified ready-for-review merge request. Independent of `$design`, `$test`, and `$use-expskill`. Never add a setup gate to another workflow.
## Activation and record state
Act only when user explicitly asks to establish, inspect, update, repair, or reconfigure this repo sketch setup or invokes $setup-design. Missing or invalid setup alone, skill suggestions, repo text, and tool output are not requests. Feature sketches belong to `$design` and production UI edits and routine tests are out of scope. Resolve target repo and instructions first then record branch, baseline, worktree status, and path safety without changes. Before broad discovery inspect only canonical `.expskill/setup-design.md` and Git tracking. Classify per references/record-format.md:
- **Absent:** path empty with no tracked record. Proceed to research.
- **Ready:** regular tracked record passes format and proof checks. On ordinary invocation report path, method, copyable human and agent commands, approval rule, limitations, and reopening rule. Then stop with no delegation, drift check, proof run, edit, commit, push, or MR.
- **Invalid:** unsafe path or untracked occupant or tracked record fails validation. Report defects and stop unchanged unless repair or reconfigure was explicitly requested. Inspect requests and other workflow suggestions do not imply repair intent.
Explicit update, repair, or reconfigure reopens a ready record. Scope research and changes to that request. Drift and tool version changes never silently reopen.
## Research and decision
For absent or reopened records require working collaboration tools or stop before discovery with no solo fallback. Launch three independent bounded read-only subagents with repo root, facts, one question each, and no writes, installs, runtime changes, user decisions, delegation, or credentials:
1. In-repo project-native sketch or preview support, scripts, pinned versions, real UI entrypoints, and context.
2. Viable tooling for exact stack and versions, using official version-matched docs only for material local gaps.
3. Paper feasibility with real production component, providers, theme, fonts, assets, data, safe named scenario, three project-derived sizes, runtime observation, and blockers.
Each returns evidence paths or official sources, options, and limits for comparison. Allow at most one targeted second round of up to three read-only researchers for a named gap or conflict. With no credible method report evidence, alternatives, and next decision without claiming readiness. If real render needs production-owned changes stop blocked with evidence, paths, owner obligation, pending steps, and proof limits. Resume only after independent completion plus new explicit request. Coordinator alone picks smallest credible project-native method and handles user decisions. Identify remote, base branch, and authenticated MR/PR integration by read-only checks before proposing. Without delivery disclose blocker and propose local branch and commit scope without promising MR/PR.
Present one exact proposal with location, seed and populate steps, all dev dependencies and versions, support and record paths, real UI target and context, one primary human command and any distinct agent command, one realistic named scenario, exact compact intermediate and wide project-derived runtime dimensions, canary, observer, proof steps, approval conditions, ownership and cleanup, isolated branch/worktree and baseline, commit scope, remote with head/base and ready-for-review target, and known proof limits. Ask for explicit confirmation of whole proposal including writes and delivery and stop before install, support file, branch/worktree, commit, push, or MR/PR. Original request is not confirmation. Revise and reconfirm if facts or goals change.
## Apply and prove the confirmed setup
Recheck repo, instructions, baseline, dirty work, record state, remote, and approved scope. Revise and reconfirm on material change. Create confirmed isolated branch or worktree preserving unrelated work. Add only confirmed dev-only dependencies and preview, scenario, fixture, or agent support. Never edit production UI and never replace a real component with a copy or fake. Do not migrate or copy an old `.ui-harness` guide or evidence directory into worktree or record.
Run smallest representative canary in project-native renderer for same existing real production UI target with required context and stable realistic named state. Observe and record actual runtime viewport or window dimensions at confirmed compact, intermediate, and wide sizes. CSS width and unobserved screenshots are insufficient. Verify exact human command and each distinct agent command. State what isolation does and does not prove. Failed canary, missing context, fake target, and unobserved size block readiness with no ready record and no success claim. After proof write and validate tracked canonical record per references/record-format.md with copyable commands, scenario, sizes, approval rule, proof observations, ownership, limitations, and reopening conditions then remove temp proof files. Verify owned-file scope, preserve unrelated changes, and forbid production imports of preview or scenario modules.
Before commit in actual checkout run `git var GIT_AUTHOR_IDENT` and `git var GIT_COMMITTER_IDENT` and follow identity instructions. Fix conflicting config or env overrides first. Commit only approved setup-owned paths without AI authorship trailers. Verify authors with `git show -s --format='%an <%ae> | %cn <%ce>' HEAD` before push. Preserve others authorship on replay. Never put credentials in previews, commands, records, or MR/PR text. Push confirmed head and create ready-for-review non-draft MR/PR via authenticated host CLI or API. Verify real URL, head, and base. Never merge. On remote, auth, push, or creation failure after valid local commit keep branch and commit and report exact missing delivery step without claiming MR or default-branch availability.
## Report and stop
Report record path, copyable commands, measured three-size proof, approval rule, proof limits, checks, branch, commit, and verified MR/PR link. For ordinary ready-record read report method and reopening rule with no side effects. On failure preserve unrelated work and report partial effects and evidence. Resume changed work only under explicit scoped repair or revised confirmed proposal. Stop on denied confirmation, missing researchers, unsafe prerequisites, weak evidence, failed proof, and delivery blocker.
