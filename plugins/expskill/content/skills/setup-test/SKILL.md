# Setup Test
Establish reusable project-native test-method matrix so agents can test their own work. Independent of `$use-expskill`, `$plan`, `$design`, `$implement`, and `$test`. Keep setup gates, setup checks, and automatic setup notices out of every other workflow.
## Activation and record state
Only the user's explicit request activates this skill: a test-method setup request or $setup-test invocation to establish, inspect, update, repair, or reconfigure this setup. Resolve target repo and read its instructions before discovery. Only note branch, baseline, worktree status, Git safety, intent, and record state as they stand. Before broad discovery inspect only root-relative `.expskill/setup-test.md` and Git tracking. Read [the record format](references/record-format.md) and classify.
- **Absent:** Path unoccupied with no tracked record. Proceed to research on explicit setup request.
- **Ready:** Regular tracked record passes format and proof checks. On ordinary invocation read it and report path, matrix, canary versus full rules, human versus agent split, routine path, and limitations with reopening rule. Then stop with no other action.
- **Invalid:** Path unsafe or occupied by untracked file, or tracked record fails validation. Report exact defects and stop unchanged unless user explicitly requested repair or reconfigure.
Only explicit update, repair, or reconfigure request reopens ready record, scoped to that request and existing record, even after drift, tool updates, or source changes. Proof needs runnable commands, and readiness needs every confirmed matrix suite runnable.
## Research and decision
For absent or reopened records, discovery runs only through working subagent tools. Without them, stop before discovery and report gap. Launch three independent bounded read-only researchers. Brief every researcher, second round included, only with repo root, credential-free project facts, its question, and reading and reporting as its only action. Questions cover test scripts with CI config plus suites plus pinned versions and environments, version-matched official runner docs only where local evidence leaves material gap, and gap with feasibility risks on paper including unrunnable commands, fake-green vectors, flake, environment and secret needs, and production-owned blockers.
Each researcher returns evidence paths or official sources, viable options, and limits. Coordinator compares findings with TMMi-L2-lite across policy, plan, monitoring, design and execution, and environment, plus pyramid labels per suite. Allow at most one targeted second round of up to three read-only researchers for named gap or conflict. If no credible runnable matrix remains, report evidence, alternatives, blockers, and next decision, state setup as blocked, and stop. Coordinator alone picks smallest credible matrix and owns user decisions.
Before proposing check remote, base branch, and authenticated merge-request integration with read-only checks. With delivery unavailable, disclose blocker and propose only local branch and commit scope. Present one exact proposal with test-type-to-command mapping with scopes plus owned record and support paths, canary versus full rule plus human versus agent split plus routine post-setup path, gap fixes limited to approved test config, scripts, agent-support files, and dependencies, with oracles unedited, every test and suite exit keeping its real pass condition, agent-routine snapshots unchanged, and CI and local meanings distinct, and record contents plus owned paths plus temporary evidence cleanup plus isolated branch or worktree and baseline plus commit scope plus remote with head and base and ready-for-review target.
Ask for explicit confirmation of that whole proposal including writes and delivery and stop before installs, files, branches, commits, pushes, or merge requests. Only explicit answer to this proposal confirms it. Any change to facts, matrix, files, dependencies, commands, branch, or delivery target needs revised reconfirmation before dependent effects.
## Apply and prove the confirmed setup
Recheck repo, instructions, baseline, dirty work, record state, remote, and approved scope and revise and reconfirm if material facts changed. Keep target read-only until confirmation, then create isolated branch or worktree while preserving unrelated work. Add or change only confirmed config, scripts, support files, and approved dependencies. Keep test oracles unedited, pass conditions real, agent-routine snapshots unchanged, CI and local meanings distinct, results only from captured runner output, and scope as confirmed. Install, commit, push, publish, or open merge requests only after confirmation. Run representative canary and full-suite sample in project runners to prove captured exit codes, test counts, layer labels, and flake notes with any re-run, and verify human command and any distinct agent command. State proof limits. Write ready record or claim success only after every suite run and command passes with executed exit code. Otherwise report blocked.
After proof write and validate tracked record with [the record format](references/record-format.md) including status, inventory, matrix with scopes, canary versus full rule, human versus agent split, routine path, gap fixes, proof with exit codes, ownership, limitations, and reopening. Remove temporary proof files. Keep owned scope, preserve unrelated changes, and exclude unrelated dirty work, customer data, secrets, and transient files. Before commit in actual checkout run `git var GIT_AUTHOR_IDENT` and `git var GIT_COMMITTER_IDENT`, follow Git identity instructions and fix conflicts or overrides first, commit only approved owned paths, with any authorship trailer naming a human, verify author and committer with `git show -s --format='%an <%ae> | %cn <%ce>' HEAD` before pushing, preserve other authorship on replays, and name credentials only by env var name in commands, records, and merge-request text.
Push confirmed head and create ready-for-review non-draft merge request through authenticated host CLI or API and verify real URL, head, and base. Leave merging to user. On remote, authentication, push, or creation failure, keep local branch and commit, claim only those, and report exact missing delivery step.
## Report and stop
Report record path, copyable commands, proof observations with exit codes and counts, gap fixes, limitations, commit, and verified merge-request link with head and base and checks, or truthful blocker with local branch and commit and missing host step. On failure preserve unrelated work and report exact partial effects and evidence. Resume only on explicit scoped repair or revised confirmed proposal. Routine testing, failing-test repair, feature, or design requests stop at boundary for relevant workflow. On cancel, stop and report approved work already done as the only further effect. Stop successfully after read-only ready report or verified setup with ready-for-review merge request. Stop unchanged on missing research tools, weak evidence, unsafe prerequisites, failed proof, or denied proposal. Report only host-returned merge-request links and count only passing suites toward success or readiness.
