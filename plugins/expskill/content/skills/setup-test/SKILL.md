# Setup Test
Establish reusable project-native test-method matrix in a Git repo, record it in tracked `.expskill/setup-test.md`, and deliver verified setup in ready-for-review merge request so an agent can test its own work. Independent of `$use-expskill`, `$plan`, `$design`, `$implement`, and `$test`. Keep setup gates, setup checks, and automatic setup notices out of every other workflow.
## Activation and record state
A missing or invalid record alone leaves it inactive, even inside `$use-expskill`, `$plan`, `$design`, `$implement`, or `$test`. Only the user's explicit request activates it: a request for test-method setup or an invocation of $setup-test to establish, inspect, update, repair, or reconfigure this setup. Resolve target repo and read its instructions before discovery. Only note branch, baseline, worktree status, Git safety, intent, and record state as they stand. Before broad discovery inspect only root-relative `.expskill/setup-test.md` and Git tracking. Read [the record format](references/record-format.md) and classify.
- **Absent:** Path unoccupied with no tracked record. Proceed to research on explicit setup request.
- **Ready:** Regular tracked record passes format and proof checks. On ordinary invocation read it and report path, matrix, canary versus full rules, human versus agent split, routine path, and limitations with reopening rule. Then stop. The report is the only action.
- **Invalid:** Path unsafe or occupied by untracked file, or tracked record fails validation. Report exact defects and stop unchanged unless the user explicitly requested repair or reconfigure.
Only an explicit update, repair, or reconfigure request reopens a ready record, scoped to that request and existing record, even after drift, tool updates, or source changes. Proof needs runnable commands, and readiness requires every confirmed matrix suite to be runnable.
## Research and decision
For absent or reopened records, discovery runs only through working subagent tools. If they are missing, stop before discovery and report the gap. Launch three independent bounded read-only researchers. Brief every researcher, second round included, only with the repo root, credential-free project facts, its question, and reading and reporting as its only action. Questions cover test scripts with CI config plus suites plus pinned versions and environments, version-matched official runner docs only where local evidence leaves material gap, and gap with feasibility risks on paper including unrunnable commands, fake-green vectors, flake, environment and secret needs, and production-owned blockers.
Each researcher returns evidence paths or official sources, viable options, and limits for the coordinator to decide on. Coordinator compares findings with TMMi-L2-lite across policy, plan, monitoring, design and execution, and environment, plus pyramid labels per suite. Allow at most one targeted second round of up to three read-only researchers for named gap or conflict. If no credible runnable matrix remains, report evidence, alternatives, blockers, and next decision, state the setup as blocked, and stop. Coordinator alone picks smallest credible matrix and owns user decisions.
Before proposing check remote, base branch, and authenticated merge-request integration with read-only checks. If delivery is unavailable, disclose the blocker and propose only local branch and commit scope. Present one exact proposal with test-type-to-command mapping with scopes plus owned record and support paths, canary versus full rule plus human versus agent split plus routine post-setup path, gap fixes limited to approved test config, scripts, agent-support files, and dependencies, with oracles unedited, every test and suite exit keeping its real pass condition, agent-routine snapshots kept unchanged, and CI and local meanings kept distinct, and record contents plus owned paths plus temporary evidence cleanup plus isolated branch or worktree and baseline plus commit scope plus remote with head and base and ready-for-review target.
Ask for explicit confirmation of that whole proposal including writes and delivery and stop before installs, files, branches, commits, pushes, or merge requests. Only an explicit answer to this proposal confirms it. Any change to facts, matrix, files, dependencies, commands, branch, or delivery target needs revised reconfirmation before dependent effects.
## Apply and prove the confirmed setup
Recheck repo, instructions, baseline, dirty work, record state, remote, and approved scope and revise and reconfirm if material facts changed. Keep target read-only until confirmation, then create isolated branch or worktree while preserving unrelated work. Add or change only confirmed config, scripts, support files, and approved dependencies. Test oracles stay unedited, every test and suite exit keeps its real pass condition, results come only from captured runner output, and scope stays as confirmed. Install, commit, push, publish, and open merge requests only after confirmation. Run representative canary and full-suite sample in project runners with exit-code capture to prove exit codes, test counts, layer labels, and flake notes with any re-run, and verify human command and any distinct agent command. The agent routine keeps snapshots unchanged, and CI and local meanings stay distinct. State proof limits. Write the ready record and claim success only when every run suite passed with an executed exit code and the human and any agent command ran. Otherwise report the setup as blocked.
After proof write and validate tracked record with [the record format](references/record-format.md) including status, inventory, matrix with scopes, canary versus full rule, human versus agent split, routine path, gap fixes, proof with exit codes, ownership, limitations, and reopening. Remove temporary proof files. Keep the commit to owned, non-transient paths, where data in the commit is synthetic and credentials appear only as env var names, and leave unrelated changes untouched and uncommitted. Before commit in actual checkout run `git var GIT_AUTHOR_IDENT` and `git var GIT_COMMITTER_IDENT`, follow Git identity instructions and fix conflicts or overrides first, commit only approved owned paths, with any authorship trailer naming a human, verify author and committer with `git show -s --format='%an <%ae> | %cn <%ce>' HEAD` before pushing, preserve other authorship on replays, and name credentials only by env var name in commands, records, and merge-request text.
Push confirmed head and create ready-for-review non-draft merge request through authenticated host CLI or API and verify real URL, head, and base. Delivery ends at the verified ready-for-review merge request. On remote, authentication, push, or creation failure, keep local branch and commit, report exact missing delivery step, and claim only the local branch and commit.
## Report and stop
Report record path, copyable commands, proof observations with exit codes and counts, gap fixes, limitations, commit, and verified merge-request link with head and base and checks, or truthful blocker with local branch and commit and missing host step. For an ordinary ready-record read, report method and reopening rule as the only effect. On failure preserve unrelated work and report exact partial effects and evidence. Resume only on explicit scoped repair or revised confirmed proposal. Routine testing, feature, or design requests stop at boundary for relevant workflow. On cancel, stop and report approved work already done as the only further effect. Stop successfully after read-only ready report or verified setup with ready-for-review merge request. Stop unchanged on unrequested invalid repair, missing research tools, weak evidence, unsafe prerequisites, failed proof, or denied proposal. Stop after at most one researcher follow-up if matrix stays unproven. Report only host-returned merge-request links, report a missing one as a blocker, and count only passing suites toward success or readiness.
