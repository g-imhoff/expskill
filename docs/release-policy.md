# Release Policy

ExpSkill uses base version `0.1.0`. A local installation may append a
SemVer build-metadata cachebuster generated by the canonical plugin helper.
Changing plugin content requires a new cachebuster and a fresh Codex session.

A release is allowed only when all of the following evidence gates pass:

1. The complete acceptance suite passes on supported Linux, Python, Git, and
   Codex versions.
2. Compatibility checks validate every installed skill, profile, policy, and
   public command boundary.
3. Security verification produces a valid signed receipt bound to the exact
   package, policy, test evidence, and release context.
4. Live certification uses fresh installed-plugin sessions and retains the raw
   evidence required to independently reconstruct each result.
5. The candidate meets the quality floor for every case and cohort; aggregate
   success cannot hide a localized quality regression.
6. Against the declared baseline, median billable token use is reduced by at
   least 50% and p95 elapsed latency is reduced by at least 30%.

Release automation must depend on acceptance, compatibility, receipt, and
certification. A missing, stale, malformed, or failed artifact blocks release.
Evidence is retained for the positive duration declared by the executable job
specification and must be newly created beneath the job workspace.

Publication happens only from a clean integrated branch after independent
read-only review and verification. The cachebuster is updated after those
gates, then the plugin is reinstalled and smoke-tested in a new session.
